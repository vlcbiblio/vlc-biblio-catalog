# Правила возрастных и жанровых категорий

Постоянное правило пользователя от 15.11.2026 применяется к каждой новой книге и содержательному изменению записи. Проверенные решения хранятся по стабильному ID в `data/book-categories.json`. Это отдельный слой: он не заменяет `data/books.js`, владельцев, наличие, поля заявок или маршруты Telegram.

## Проверка каждой записи

1. Сравнить название, автора, ISBN и аннотацию с последним проверенным решением. Изменение обложки, наличия или фонда само по себе не меняет возраст или жанр. Разные экземпляры и издания не объединять только по названию.
2. Проверить конкретное произведение и цикл. Искать сначала по ISBN, затем по названию/автору: издатель, национальная или публичная библиотека, надёжный книжный каталог. Сохранять URL, дату и основание. Не считать поисковую ссылку или неудачное обращение подтверждением.
3. Определить жанр по содержанию, а не по отдельному слову или автору. Разные циклы одного автора требуют разных решений: детективы Мейзи и фэнтези Лотти у Холли Вебб не взаимозаменяемы. Жанры могут сочетаться; новые рубрики вводить только по смыслу и с метками RU/ES.
4. Рекомендовать возраст по сложности текста, форме, темам и адресации. Базовые группы интерфейса: 0–3, 4–6, 7–10, 11–14, 15–17 лет, взрослые. Точные рекомендации 12–14 или 16–17 сохраняются и участвуют в широких фильтрах по пересечению диапазонов. Не назначать взрослых из-за отсутствия детской метки и младенцев из-за 0+.
5. Отдельно проверить маркировку конкретного издания. Не переносить её с другого ISBN или электронной версии. Рекомендация не должна включать возраст ниже подтверждённого ограничения издания. Противоречие нужно перепроверить и описать, а не механически принимать число.
6. Сохранить обоснованное решение. При отсутствии готового внешнего возрастного/жанрового поля допустима редакционная рекомендация по проверенному содержанию. Если даже содержание нельзя установить, запись остаётся `pending_review`, а не считается завершённой или автоматически взрослой. Нужные сведения/фото запрашиваются у владельца процесса.

## Поля и происхождение

- `identity`: текущее название, автор, ISBN и аннотация из публичного реестра. По ним проверяется, применимо ли прежнее решение.
- `reader_age_groups`, `genres`: содержательные категории.
- `reader_age_status`: `external_catalog` только при прямом подтверждении адресации; иначе `editorial_recommendation`. `genre_status`: соответственно `external_catalog` или `editorial_review`.
- `reader_age_basis`, `genre_basis`: основание именно этой книги/серии. `reader_age_sources`, `genre_sources`: источники подтверждённых полей.
- `edition_age_ratings`, `edition_rating_status`, `edition_rating_sources`: отдельная маркировка конкретного издания.
- `external_match` и `sources`: сопоставление издания по названию/ISBN либо произведения по автору и названию. Наличие внешней карточки не подтверждает автоматически каждый признак.
- `research_sources`, `research_scope: work_or_series_reference`: вспомогательные материалы о произведении/цикле, не доказательство ISBN. Дата решения — `classification_review_date`, замечание — `editorial_note`.

## Ручное обновление и сборка

Для существующих записей сохранить проверенные решения по ID. Новые или изменившиеся название/автор/ISBN/аннотация до ручной проверки получают явное `pending_review`. При этом `data/book-categories.json` сохраняется: экспорт и генерация не стирают прежние решения. Старое поле `audience` не служит возрастной рекомендацией.

Можно вручную обновить соответствующий объект в `data/book-categories.json`, включая `identity` и основания после проверки. Затем собрать публичные страницы только из текущего публичного реестра:

```powershell
python -X utf8 generate_catalog_site.py
```

Для переноса полного заранее проверенного snapshot есть отдельный импортёр:

```powershell
python scripts/import_book_categories.py --source PATH_TO_REVIEWED_JSON
python -X utf8 generate_catalog_site.py
```

Snapshot должен содержать `source_sha256`, `date` и `books` с категоризацией каждого текущего ID. Импортёр проверяет SHA публичного `data/books.js`, идентичность и полный набор ID; он не читает частный CSV. Активный `data/book-categories.js` пересобирается из хранилища решений, а его cache-buster обновляется в шаблонах.

После изменений проверить инкремент и сохранить исходный дизайн и сценарии Telegram. Выполнить релевантные тесты, локальную RU/ES desktop/mobile проверку и независимое ревью. Публикация регулируется `PUBLISH.md`. Фоновый автоклассификатор или новая интеграция с ботом этим процессом не создаются.
